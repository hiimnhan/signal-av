A network built for a 2d-length input has no defined behaviour on a 5d or 0d one. The usual patch — pad every step out to K·d with zeros — brings back the slot-order problem from the panel above, since now the network must also learn which zero-blocks mean "no neighbour here" versus a genuinely quiet one.

Empty slots are masked out of the sum, not fed in as zeros pretending to be real neighbours — 0 present and 5 present both land on the exact same (d,) shape, so ρ is one fixed-size network for every occupancy, no padding trick required.

Why it matters here: the K nearest neighbours are reassigned to slots every step as the traffic scene changes — there's no persistent identity behind "slot 2." Concatenation's output shape (K·d,) encodes which slot each embedding came from, so the MLP after it would have to learn permutation-invariance from data — spending parameters and samples on a symmetry the problem already guarantees. DeepSets' sum collapses (K, d) to (d,) before the MLP ever sees it: z = ρ(Σ₀ φ(neighbour₀)). The invariance is a property of the shape transformation itself, not something learned.
